# WuNa - Encrypted Local Network Chat

![WuNa Banner](https://i.imgur.com/v5O8J1A.png)

WuNa is a lightweight, secure, and easy-to-use encrypted chat application designed for local network communication. It ensures that all your conversations are kept private by using robust end-to-end encryption.

## Features

-   **Strong End-to-End Encryption:** Utilizes the Fernet symmetric encryption scheme from the `cryptography` library to ensure that only the sender and receiver can read the messages.
-   **Multi-User Chat Room:** A central server broadcasts messages to all connected clients, creating a group chat environment.
-   **Graphical User Interface:** A user-friendly GUI built with `tkinter` for a more intuitive chatting experience.
-   **Cross-Platform:** Being a Python application, it can run on any operating system with Python installed.
-   **Simple Setup:** No complex dependencies or configuration. Get up and running in a few simple steps.

## Project Structure

```
wuna/
├── .gitignore
├── client.py
├── crypto.py
├── README.md
├── requirements.txt
└── server.py
```

-   `server.py`: The main application that listens for and manages client connections.
-   `client.py`: The application that connects to the server, allowing users to send and receive messages.
-   `crypto.py`: A helper module that handles all encryption and decryption logic.
-   `requirements.txt`: A list of all the Python dependencies required to run the application.
-   `secret.key`: (Generated) This file contains the secret key for encryption. It is generated by the server on its first run.

## How to Use

### 1. Prerequisites

-   Python 3.6 or higher
-   `pip` for installing dependencies

### 2. Installation

First, clone the repository to your local machine:

```bash
git clone https://github.com/your-username/wuna.git
cd wuna
```

Next, install the required Python libraries:

```bash
pip install -r requirements.txt
```

### 3. Key Generation and Distribution

The chat is secured by a symmetric encryption key. This key must be the same for the server and all clients.

**On the Server Machine:**

1.  Run the server for the first time. It will automatically generate a `secret.key` file in the `wuna` directory.
    ```bash
    python server.py
    ```
2.  The server is now running. Keep this terminal open.

**On the Client Machines:**

1.  You need to copy the `secret.key` file from the server machine to the `wuna` directory on each client machine. You can do this using a USB drive, a secure network copy (SCP), or any other secure method.
2.  **Important:** The `secret.key` file must be in the same directory as the `client.py` script.

### 4. Running the Application

**Server:**

Start the server by running:

```bash
python server.py
```

The server will display a message indicating that it is listening for connections.

**Client:**

Once the `secret.key` is in place, you can start the client:

```bash
python client.py
```

A dialog box will pop up asking for your username. After entering it, the main chat window will appear, and you can start sending and receiving messages securely.

## How It Works

-   **Server (`server.py`):** The server's primary role is to act as a central hub. It accepts connections from multiple clients and maintains a list of them. When it receives an encrypted message from a client, it broadcasts that message to all other connected clients without decrypting it.
-   **Client (`client.py`):** The client, now with a `tkinter`-based GUI, connects to the server. It provides a chat window for displaying messages and an input field for sending them. When a user sends a message, the client encrypts it using the shared `secret.key` and sends it to the server. When it receives a message from the server, it decrypts it and displays it in the chat window.
-   **Cryptography (`crypto.py`):** This module abstracts the encryption and decryption logic. It uses the Fernet algorithm, which ensures that a message cannot be manipulated or read without the key.

## Disclaimer

This application is intended for educational purposes and as a demonstration of encrypted communication. While it uses strong encryption, it has not been audited for security vulnerabilities and may not be suitable for environments that require high security. Always be cautious when sharing the `secret.key`.
